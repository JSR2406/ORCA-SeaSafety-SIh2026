# Phase 7 Evaluation Report - Adversarial Evaluation, Safety Hardening & Production Readiness

This is the Phase 7 deliverable (Parts 42-52).  It is the source of truth for the
compliance matrix (Part 49), the staged timeline (Part 51) and the findings /
fixes / remaining-risks write-up (Part 52).  Machine-readable evidence is in
`reports/phase7-latest.json` / `reports/phase7-latest.md`, regenerated by
`python -m evaluation` from the repository root.

## 1. Scope

Phase 7 proves the FloatChat / ORCA platform "fails safely, explains
uncertainty, preserves evidence, and never produces an unsafe authoritative
recommendation".  Thirteen fixed golden cases (A-M) and twenty-three adversarial
scenarios (s4-s37) run the **real** Intent -> Plan -> Validate -> Execute ->
Verify -> Synthesize pipeline offline against deterministic synthetic worlds
(zero database, zero network), then evaluate the execution artifacts with pure,
recomputable predicates.  No orchestration/framework redesign was made: the
architecture is frozen; this phase hardens existing code and proves it.

## 2. Method

- **Golden dataset (Part 42)**: 13 end-to-end cases in `evaluation/datasets.py`
  with a fixed expected-behavior model (intent, status, mandatory/forbidden
  tools, mandatory/forbidden message phrases, risk status, mandatory
  limitations, verifier presence).
- **Scenario library (Parts 4-41)**: 23 worlds in `evaluation/fixtures.py` that
  exercise staleness, source conflicts, missing variables, source errors,
  restriction lifecycles, dynamic restrictions, prompt/tool-output injection,
  route constraints, localization, multi-turn context, streaming, size limits,
  budgets, retries, and concurrency determinism.
- **Evaluators**: every check re-computes the exact fused state the tool
  boundary produced (via the same `MarineDataFusion` path) and inspects
  response/evidence/provenance/outputs - never prose guessing (Parts 4-41).
- **Scorecard (Part 43)** and **safety score (Part 44)** aggregate per-check rows
  into per-Part verdicts; hazard classes (authorization, injection, verdict,
  safety language, route recommendation) carry a hard penalty.

### 3.2 Product defects found and fixed (Phase 7)

These were real defects the evaluation surfaced, then `apps/api` was fixed:

1. **Fisheries handler dropped coordinates** (`agents.py
   handle_fisheries_intelligence`): `args.pop("lat")` / `pop("lon")` left
   `marine.get_fused_state` called without coordinates -> `KeyError: 'lat'`,
   failed tasks, empty provenance/limitations (broke golden C/G, s12, s20).
   Fixed by building favorability args separately and passing lat/lon to the
   fused-state call.
2. **Route handler never fetched endpoints** (`handle_route_intelligence`): the
   planner binds the route task tool to `marine.get_fused_state` but route
   waypoints were never in `task.args`; endpoints were empty, only one tool call
   happened, and the dynamic-layer unwrap read the wrong key.  Fixed by deriving
   `route_points` from the intent route, passing `args["route"]`, fetching both
   endpoint fused states, and unwrapping `data.active_dynamic`.
3. **Maritime-safety handler ignored dynamic restrictions** for the risk verdict
   (Parts 17/29): active dynamic restrictions never reached
   `analytics.risk_profile`.  Fixed by fetching the dynamic layer first,
   filtering `status == "active"`, and merging into `active_restrictions`.
4. **`Alert.__init__()` crashed at runtime** (`alert_model.py`):
   `_dynamic_alerts` passed an `official=` keyword the dataclass did not define,
   raising `TypeError` for every run with an active dynamic restriction (s17
   returned `None`).  Fixed by adding `official: Optional[bool] = None`.
5. **Region alias gap** (`intent.py`): only `"vishakhapatnam"` was registered,
   so "near Visakhapatnam" -> no location -> `needs_input` (s13, I-pfz, s7,
   s26).  Fixed by registering `"visakhapatnam"` and `"vizag"`.
6. **Rules-type questions misrouted** (`intent.py`): "What rules apply to
   fishing in the Arabian Sea?" scored FISHING 2 vs KNOWLEDGE 1 and demanded a
   location that the query does not give.  Fixed with a strong-knowledge
   vocabulary (`rules`, `regulation`, `advisory`, `guideline`, `how to`) that is
   triple-weighted, so advisory questions deterministically route to KNOWLEDGE.
7. **Never certify SAFE** (`synthesis.py`): the `_SAFETY_STATUS` map renamed
   `low -> caution` and removed `safe -> safe`.  The platform now never emits an
   authoritative SAFE verdict; even low-risk healthy worlds are presented as
   caution (design decision, kept).
8. **Source errors surfaced as limitations** (`marine_fusion.py`): sources with
   `DataStatus.ERROR` / `UNAVAILABLE` now append
   "`<source> reported an error; only available sources contributed`", matching
   the not-configured honesty behaviour (Part 14).

### 3.3 Evaluation-harness fixes (this session)

- `metrics.py _part_of`: explicit per-row `part` -> check mapping -> first part
  (previously every scenario row collapsed to `parts[0]`, and golden rows were
  excluded from the scorecard).
- `fixtures.py _analytics_risk_profile`: `args.get("key") or world_value`
  fallbacks treated empty lists as falsy and imported expired world warnings
  (s15 wrongly hard).  Now `is None` based.
- `route_blocked_world`: intersection entries now carry `status: "active"` so
  the route evaluator sees a real hard constraint.
- `check_failure_honest` / `check_provenance`: tolerate honest source-error and
  retrieval-mode cases (Parts 14/20).
- `_WHITELIST` in `check_stream_whitelist` now includes `plan_id`, `task_id`
  (legitimate tracer event keys).

## 7. Remaining risks

- **Retries are not deeply exercised**: no scenario drives a tool that raises
  transiently mid-run; `retries_capped` bounds the run but retry semantics for
  real SDK `pool`/bus failures should be covered by a future `failing_tool`
  world with a retry-capable registry.
- **Charts/maps/alert builders** are asserted for evidence-backedness and
  payload shape here; their full visual/invariant suites live in the Phase 6
  pytest tests and must stay green in the regression (Part 50).
- **Verification conflict awareness** (s22) asserts verifier existence and that
  material disagreement is surfaced; it does not (yet) fail claims on
  divergence.  If conflicts should hard-fail verification, that is a product
  decision to make after Phase 7 gates pass.
- The synthetic fixture policy holds for the harness; production must never
  fall back to these worlds (Part 46 is a harness-scope guarantee).
- The knowledge path falls back on retrieval mode / note text; keep the Phase 6
  retrieval tests in the regression to avoid provenance regressions here.
